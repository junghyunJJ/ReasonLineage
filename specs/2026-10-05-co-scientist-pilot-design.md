# Co-Scientist 연구 가설 비교 파일럿 설계

날짜: 2026-10-05. 브랜치: `co-scientist-pilot`.
상태: 인터뷰 합의를 구체화한 서면 설계. 구현 전 검토용이며 모델 생성 실험은 아직 시작하지 않았다.

## 1. 목표와 완료 기준

동일한 질문·문헌 자료와 비슷한 전체 연산 예산에서 ReasonLineage의 다중 모델 생성·비판·진화가 단일 모델의 반복 수정에 추가 가치를 제공하는지 확인한다. 내부 fitness와 연구 가설의 품질을 구분한다.

파일럿 완료 기준은 계획한 10개 실행에 대해 완료·실패·상한 중단을 명시하고, 완료된 답의 요청·응답·사용량·계보, 문헌 검증 자료, 독립 LLM 평가와 전문가용 익명 패킷을 준비하는 것이다. 전문가 값은 사용자가 수집한다. 값이 오기 전에는 주 평가 결과를 주장하지 않는다. 두 문제의 단회 실행은 일반적인 우위의 통계적 입증이 아니다.

## 2. 합의한 범위

- ALS 기전 가설 생성과 AML 약물 재창출을 모두 포함한다.
- ReasonLineage와 GPT·Opus·Grok·GLM Flash의 단독 방법을 각각 비교한다.
- 문제당 방법별 1회, 총 10개 최종 산출물을 목표로 한다.
- 생성 단계의 입력 문헌을 고정한다. 사후 문헌 검증은 별도로 한다.
- 전문가 블라인드 평가가 주 평가이며 문헌 검증과 별도 LLM 평가를 함께 수행한다.
- GLM은 `glm-5.3-flash`를 사용한다.
- 최초 모델 요청부터 자동 실행 단계의 전체 경과시간 상한은 4시간이다. 문헌 자료 작성과 전문가 평가 대기는 제외한다.
- 기존 측정 자료, `configs/main.json`, 기본 프로토콜 1.0.5와 로컬 `main`은 유지한다. 새 워크트리에 실험 전용 설정과 실행 도구를 추가한다.

## 3. 질문과 고정 문헌 자료

ALS는 Co-Scientist 보충자료 Note 10의 핵공 단백질 인산화 관련 입력 예시를 바탕으로 한다. 그 예시를 본문의 실험 검증 사례와 구분한다. 핵공 단백질의 특정 인산화가 원인이라는 명제를 정답으로 제공하지 않는다.

AML은 기존 적응증이 있는 약물의 새로운 AML 적용 가설을 기전·맥락·검증 전략과 함께 제안하는 문제다. 기존 repoDB의 승인 약 고르기를 재사용하지 않는다. Co-Scientist의 실험 양성 후보 목록을 유일한 정답이나 생성 입력으로 사용하지 않는다.

정확한 질문과 원저 논문 네 편씩의 요약·한계는 [ALS 자료](../research/co-scientist-pilot/als-evidence.md)와 [AML 자료](../research/co-scientist-pilot/aml-evidence.md)에 있다. PubMed/PMC의 DOI·PMID·제목·초록을 확인했다. 같은 파일을 모든 생성·심사·수정 요청에 공급하고 실행 전에 내용·SHA-256을 고정한다. 큐레이션 편향과 모델의 기존 학습 기억은 한계로 명시한다.

## 4. 모델과 출력

설정은 `configs/co-scientist-pilot.json`을 사용한다.

| 이름 | 모델 | 설정한 추론 수준 |
|---|---|---|
| opus | claude-opus-5-5 | xhigh |
| gpt | gpt-6.1-sol | xhigh |
| grok | grok-4.7 | xhigh |
| glm | glm-5.3-flash | max |

모든 작성 요청은 가설 하나를 400–800단어의 같은 구조로 작성한다: 가설, 기전과 근거, 명시적 가정, 대안, 판별 가능한 연구 전략, 반증 결과와 한계. 모델·방법·세대·이전 대화에 대한 메타 언급을 하지 않도록 한다. 현재 `answer/ranking` 형식과 호환시키되 `ranking`은 가설 제목 하나만 담는다. 작성자의 확신도는 독립 품질 점수가 아니다.

기존 격리 백엔드를 사용한다. 실험 전용 프로토콜과 해시를 별도로 기록한다. 이전 실행을 가져오거나 결과 폴더를 재사용하지 않는다. J1 및 기존 checkers의 추가 호출은 이 실험에 사용하지 않는다. 내부 심사는 현재 biomedical 차원·가중치를 양쪽에 동일하게 적용하고 사실·가정 구분을 공통 지침에 넣는다.

## 5. 다중 모델과 단독 방법

초기 후보 수와 심사 수를 맞춘 강한 단독 비교를 사용한다. 단독 방법도 여러 초안과 새 세션의 자기 비판을 허용한다.

| 단계 | ReasonLineage | 단일 모델 반복 수정 |
|---|---|---|
| 초기 후보 | 네 모델이 하나씩, 총 4개 | 해당 모델이 새 세션으로 4개 |
| 후보별 내부 심사 | 작성자 제외 세 모델 | 같은 모델의 새 세션 3개 |
| 선택 | 기존 fitness·생존자 규칙으로 2개 유지 | 같은 규칙으로 2개 유지 |
| 다음 후보 | 1위 변이 1개 + 두 생존자 교차 1개 | 각 생존자를 자기 비판으로 수정한 후보 1개씩; 교차 없음 |
| 반복 | 3세대 | 3라운드 |
| 최종 답 | 최종 개체군 내부 fitness 1위 | 같은 최종 선택 규칙 |

완전한 실행 하나는 작성 10회, 심사 30회, 총 40회 요청이다. 10개 실행은 최대 400회, 독립 LLM의 순서 점검을 포함하면 정상 완료 시 404회 요청이다. 단독 비판 세션은 같은 모델을 새로 호출하는 것이며 모델 종류를 추가하지 않는다. 두 방식의 교차 여부와 작성자 다양성 차이는 해석에 명시한다.

## 6. 사용량과 4시간 상한

같은 호출 수가 같은 계산량이라는 주장을 하지 않는다. 모든 내부 작성·심사·수정의 입력·출력 토큰, 제공되는 추론 사용량, 대기·실행 시간과 확인 가능한 비용을 기록한다. 제공자의 비용 추정치와 실제 청구금액을 구분한다.

- 실행당 최대 40회 요청, 최대 400,000개 보고된 입력+출력 토큰, 최대 20분을 허용한다.
- 요청별 timeout은 5분과 해당 실행·전체 남은 시간 중 작은 값이다. HTTP 출력 상한은 32,768토큰이다. CLI가 이를 강제하지 못하면 기록하고 응답 후 사용량을 확인한다.
- 토큰 상한은 호출 사이에 검사하는 소프트 상한이다. 시작된 요청 때문에 초과할 수 있어 실제 값·초과 여부를 기록한다. 미보고 사용량이나 실패 요청의 소비량을 0으로 간주하지 않는다.
- 생성 순서는 ALS ReasonLineage → AML ReasonLineage → ALS GPT → AML GPT → ALS Opus → AML Opus → ALS Grok → AML Grok → ALS GLM Flash → AML GLM Flash로 고정한다. 생성 실행에 최대 200분, 독립 LLM 평가에 최대 40분을 남긴다. 전체 240분 상한이 우선한다.
- 상한에서 새 요청을 시작하지 않고 진행 중인 로컬 호출을 종료한 뒤 완료 기록을 보존한다. 제공자의 미확인 원격 소비량은 확인 불가로 표시한다.
- 양쪽이 완료되고 사용량 누락이 없으며 실제 총토큰 비율(ReasonLineage / 단독)이 0.9–1.1이어야 '사용량이 비슷한 비교'로 분류한다. 분모가 0이거나 확인 불가하면 해당하지 않는다. 다른 산출물도 보고하지만 동일 예산에서의 우위로 해석하지 않는다.

동일한 호출 허용량과 최고 추론 수준을 제공한 비교, 실제 사용량이 비슷한 비교, 상한 중단을 구분한다. 실제 FLOPs는 측정하지 않는다.

## 7. 실패·기록·재개

첫 파일럿은 자동 재시도를 하지 않는다. 공급자 거부, 인증·용량·timeout 오류, 출력 형식 실패는 해당 실행의 실패나 미완료로 기록한다. 거부된 요청을 재질문하거나 표현을 바꾸지 않는다. 결과가 없는 칸을 열등한 가설로 채점하지 않는다.

질문, 자료·프로토콜·설정·코드 식별자, 입력과 공개 답변·비판, 선택과 계보, 사용량과 상태를 보존한다. API 키·인증 헤더와 모델의 비공개 reasoning 필드는 공유 자료에 기록하지 않는다. 셸은 로그인 초기화 없이 실행한다.

중단된 실행을 최종 완료 답으로 취급하지 않는다. 유효한 초기 답이 있으면 초기 기록만 보존하고 최종 칸은 미완료다. 종료 후 완료·실패·미실행 목록과 평가의 남은 항목을 보고한다. 상한 이후 재개는 별도 실행 승인과 누적 자원 기록이 필요하다.

## 8. 독립 평가와 전문가 전달물

별도 LLM은 생성 패널에 없는 `deepseek-v4.1-flash`를 기존 Ollama HTTP 경로로 사용한다. 2026-10-05 모델 목록에서 식별자를 확인했고 생성 요청은 하지 않았다. `high` 수준과 최대 16,384 출력 토큰을 사용한다. 옵션·출력 형식은 첫 정식 요청에서 검증하고 실패하면 평가를 미완료로 기록한다. 다른 모델로 몰래 대체하지 않는다.

완료된 방법의 초기 내부 1위와 최종 답을 익명화한다. 동일한 답은 같은 익명 ID로 연결해 중복 평가하지 않는다. 최대 20개 문서이며 모델·방법·단계 매핑은 전문가 패킷 밖에 둔다. 질문과 공통 문헌은 제공하지만 내부 fitness와 생성 모델 식별자는 제공하지 않는다.

LLM은 과제별 문서 묶음을 원래 순서와 역순으로 한 번씩 평가한다. 순서 변화는 편향 점검이며 독립 표본 수를 늘리지 않는다. 근거성·인과 엄밀성·구체성·검증 가능성·실행 가능성의 1–5 점수와 이유를 요청한다. 신규성은 별도 참고값이다. 평가 결과는 생성·선택에 되먹임하지 않는다.

문헌 검증은 인용 ID·PMID·DOI 실재 여부, 주장을 뒷받침하는 내용과 가정 여부를 기록한다. 패킷 밖 약물 승인·원 적응증 등은 공식 승인 자료와 원저 문헌을 추가로 확인한다. 접근·근거 확인이 불가능하면 미검증으로 표시한다. 메타데이터 확인과 주장 검증을 구분한다.

전문가의 최초 평가 때는 독립 LLM 점수, 문헌 검증자가 내린 결론과 내부 fitness를 함께 보여주지 않는다. 전문가에게는 익명 가설과 공통 입력 문헌, 원문 출처 링크만 제공해 평가 간 영향을 줄인다. 이후 세 평가를 분석 자료에서 나란히 비교한다.

전문가 양식은 [expert-review-template.md](../research/co-scientist-pilot/expert-review-template.md)이다. 최종 ReasonLineage와 네 단독 답의 비교가 과제별 주 평가, 총 최대 8개 비교다. 초기→최종은 보조다. 평점·이유·동점과 전문가 간 불일치를 보존한다. 사용자에게 익명 패킷을 전달한다.

## 9. 보고와 해석

과제별로 모든 방법의 결과와 실패·중단을 보고하고 유리한 모델·단계만 고르지 않는다. 전문가, 문헌, 독립 LLM, 내부 fitness와 자원 사용량 결과를 분리한다.

공개 목표와 출력이 학습에 포함됐을 수 있다. 이 실험은 새 생물학적 발견의 입증이나 Co-Scientist 전체 시스템의 동일 조건 재현이 아니다. 가설의 사실 여부에는 독립 실험이 필요하다. 실패·사용량 불일치를 가설 품질 열등함으로 대신 해석하지 않는다.

## 10. 구현과 검증 범위

기존 호출·기록·선택·역할 정책을 재사용한다. 새 도구는 입력/자료 식별, 예산과 상태, 다중/단독 실행, 익명화와 독립 평가의 책임으로 나눈다. 기본 엔진을 무관하게 재구성하지 않는다.

가짜 모델로 후보·심사 수와 선택, 토큰·시간 상한·미보고 사용량, 재시도 없는 실패/거부, 입력 해시, 익명화, 초기/최종 구분, 평가 피드백 격리와 부분 결과 보고를 검증한다. 실제 호출 전에 전체 오프라인 테스트를 통과시킨다. 라이브 결과는 별도로 기록한다.
