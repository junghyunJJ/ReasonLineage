# arXiv 결과 예측 정답지 (A2 세트) 설계

- 날짜: 2026-10-02
- 상태: 사용자 검토 대기
- 기반: `specs/2026-10-02-gold-biorxiv-design.md` (같은 과제 방식과 파이프라인), `specs/2026-09-30-gold-dev-design.md` (판정 규칙), `specs/2026-09-29-engine-design.md` (프로토콜 1.0.5)
- 조사: `.omc/research/2026-10-01-framework-validation-sources.md` (권장안 A)
- 브랜치: `gold-arxiv` (`gold-biorxiv` 위에서 시작)

## 1. 목적과 범위

**같은 방식을 생의학 밖에서 한 번 더 해요.** bioRxiv 세트(A)와 과제 방식은 같고 자료만 arXiv예요.

두 가지를 얻어요.
1. **일반성:** 한 분야에서만 되는 게 아니라는 근거예요. 심사 편향 논문의 주장이 분야에 매이지 않아요.
2. **안정성:** 2026-10-02에 생의학 초록이 제공자 안전 분류기에 막혀 실행이 여러 번 멈췄어요. 기계학습·물리·경제 초록에는 그 위험이 사실상 없어요.

**인터뷰에서 정한 것 (2026-10-02)**
- 분야 5개: `cs.LG`(기계학습), `cs.CL`(자연어처리), `cond-mat.mtrl-sci`(재료물리), `astro-ph.GA`(은하 천문), `econ.EM`(계량경제).
- 날짜 규칙: v1 제출일이 2026-07-01 이후이고, 아직 v1인 논문만 써요.
- 분야는 주 분류(primary category)로 가르고, 논문 하나는 한 번만 넣어요.
- 파일럿 5과제(분야당 1개) → 본 세트 20과제(분야당 4개)예요. bioRxiv와 같은 파일럿 규칙을 써요.
- **판정은 세트마다 따로 해요.** 두 세트를 합친 결과는 보조로만 봐요.

**범위 밖**
- 본문 사용, 사람이 쓴 변조문, 다른 저장소
- 2·3단계 실행과 그 판정 기준
- bioRxiv 세트의 재실행

## 2. 성공 기준

1. 같은 저장 입력(고정한 목록, 저장한 DeepSeek 출력, 검토 기록)에서 같은 과제·정답 파일이 다시 만들어져요.
2. 모든 과제의 맥락은 초록의 배경·방법 문장만이고, 진짜 결과는 정리된 초록의 결과 문장 그대로예요.
3. 엔진은 정답 파일을 읽지 않아요.
4. 수집 거르기, 수식 정리, 표본 순서, 파일 쓰기를 테스트로 확인해요. 테스트는 모델과 arXiv를 부르지 않아요.
5. 파일럿을 돌려 규칙대로 다음 단계를 정하고, 본 세트까지 가면 1단계 판정과 분석 보고서를 내요.

## 3. 구조

bioRxiv 세트와 **4.2–4.7(문장 나누기부터 파일 쓰기까지)이 완전히 같아요.** 그래서 그 부분을 공용 모듈로 옮기고, 자료마다 수집만 따로 둬요.

| 파일 | 하는 일 |
|---|---|
| `src/reasonlineage/gold/abstracts.py` (새, `biorxiv.py`에서 옮김) | 문장 나누기, DeepSeek 단계(나누기·변조·티 거르기·맥락 거르기), 검토 기록, 과제·정답 파일 |
| `src/reasonlineage/gold/biorxiv.py` (줄어듦) | bioRxiv 수집과 거르기만 남아요 |
| `src/reasonlineage/gold/arxiv.py` (새) | arXiv 수집과 거르기, 수식 정리 |
| `scripts/build_arxiv.py` (새) | `fetch` → `candidates SET` → (검토) → `build SET` |
| `gold/arxiv/pool.json`, `gold/<SET>/`, `tasks/<SET>/` | bioRxiv 세트와 같은 구조 |

- 옮기는 동안 기존 테스트는 그대로 통과해야 해요. 동작은 하나도 바뀌지 않아요.
- `scripts/run_gold.sh`, `reasonlineage gold --analysis`, 채점과 판정, 엔진은 바꾸지 않아요.
- **구현 시점:** bioRxiv 본 세트 실행이 끝난 뒤에 시작해요. 측정 중에 엔진·공용 코드가 바뀌면 실행 기록의 출처가 흐려져요.

**세트 이름:** 파일럿은 `arxiv-pilot`, 본 세트는 `arxiv-v1`이에요.

## 4. 과제 만들기

### 4.1 목록 받기 (`fetch`)
- API: `https://export.arxiv.org/api/query?search_query=cat:<분야> AND submittedDate:[202607010000 TO 202610010000]&start=<n>&max_results=100&sortBy=submittedDate&sortOrder=descending`
  - HTTP는 막혀 있어서 HTTPS만 써요. 요청 사이에 3초를 쉬어요(arXiv 권고).
  - 2026-10-02 확인: 기간 안의 논문 수는 cs.LG 13,944, cs.CL 7,153, cond-mat.mtrl-sci 2,645, astro-ph.GA 1,978, econ.EM 373편이에요.
- 남기는 기록(모두 만족)
  1. `id`가 `v1`로 끝나요. 개정된 논문은 빼요. API가 최신 버전 초록을 주기 때문에, 개정되면 초록과 첫 공개일이 어긋나요(최근 논문의 94–100%가 아직 v1이에요).
  2. `published`(v1 제출일)가 2026-07-01 이후예요.
  3. `primary_category`가 그 분야예요. 교차 등록만 된 논문은 빼요(한 페이지에서 56–70%가 주 분류예요).
  4. 초록이 120단어 이상이에요(81–96%).
  5. 수식 표기를 정리할 수 있어요(4.2).
- 남긴 기록의 arXiv id(버전 없이), 제목, 분야, 날짜, 정리한 초록을 id 순서로 캐시의 `pool.json`에 저장해요. 저장소의 색인에는 id·분야·날짜와 전체 목록의 sha256을 적어요.

### 4.2 수식 표기 정리
진짜 결과는 초록 원문이에요. 그래서 표기가 남으면 DeepSeek가 쓴 변조문과 **표기만으로 구별돼요.** bioRxiv에서 `{beta}` 때문에 생긴 문제와 같아요(그 설계 4.1).
- `$…$`의 달러 기호를 없애고, 자주 쓰는 명령을 글자로 바꿔요: `\sim`→~, `\approx`→≈, `\times`→×, `\pm`→±, `\%`→%, `\mu`→µ, `\odot`→☉, `\deg`→°, `\alpha`…`\omega`→그리스 문자, `\textit{x}`·`\textbf{}`·`\emph{}`·`\mathrm{}`→x, `~`→공백, `\_`→_, `\&`→&.
- 정리한 뒤에도 백슬래시 명령이나 `\begin{`, `\cite`, `\ref{`가 남으면 그 논문은 빼요. 한 페이지에서 `\begin`·`\cite`는 2% 미만이었어요.
- **변조문은 정리된 글에서 만들어요.** 그래서 진짜와 변조문이 같은 표기 규칙을 써요.
- 수식이 흔한 분야가 있어요(`$` 포함 비율: astro-ph.GA 67%, cond-mat 42%, cs.LG 22%, econ.EM 17%, cs.CL 11%). 정리로 대부분 살리고, 남는 것만 버려요. 분야당 논문이 수백~수천 편이라 할당량을 채우기에 넉넉해요.

### 4.3–4.7 나머지
bioRxiv 설계 4.3–4.7을 그대로 써요. 공용 모듈이 같은 코드를 쓰므로 규칙도 같아요.
- 문장 나누기와 결과 시작 문장 고르기(DeepSeek), 버리는 경우
- 변조문 2개(`reversed`, `altered`): 맥락과 모순 금지, 길이·문체·숫자 형식 맞추기
- 티 거르기(맥락 없이 3번), 맥락 거르기(맥락과 함께 3번)
- 검토 표본(분야마다 처음 남은 논문 1편), 검토 기록 규칙
- 과제 파일(`Result A/B/C`, 제목 숨김, 정답 글자는 선언한 크기로 고르게), 정답 파일

**바뀌는 것 하나:** 출처 기록(`gold.json`의 `source`)에 arXiv API, 기간, 분야, 목록 sha256, DeepSeek 모델을 적어요.

## 5. 실행 계획 (실행 전에 고정)

### 5.1 파일럿 (`arxiv-pilot`, 5과제)
- 사용자가 5과제를 검토한 뒤 `scripts/run_gold.sh arxiv-pilot`으로 돌려요. 조건은 bioRxiv와 같아요(0세대만, 프로토콜 1.0.5, seed 1, 이해관계자 배제, 맥락 격리, 웹 검색 없음).
- 규칙: 정답 비율이 0.8 이상이면 천장, 0.375 이하면 우연 수준이에요. 둘 다 아니면 본 세트로 가요.
- 파일럿은 판정에 넣지 않아요.

### 5.2 본 세트 (`arxiv-v1`, 20과제)
- 파일럿 논문을 뺀 새 표본으로 만들고, 표본 5과제를 검토한 뒤 같은 조건으로 돌려요.
- 결과를 본 뒤 과제나 판정 기준을 바꾸지 않아요.

### 5.3 비용
- 과제당 모델 호출 16회와 J1 점검 4회예요. bioRxiv에서 과제당 8–10분이었어요.
- 파일럿 약 1시간, 본 세트 3–4시간이에요. DeepSeek는 논문당 8회 안팎이고 로컬이라 비용이 없어요.

## 6. 채점과 판정
- 정답 점수와 1단계 판정은 개발용 설계 6.1–6.2를 그대로 써요(천장 80%, 쌍 10개, 일치도 0.70, 동점 0.5).
- **세트마다 따로 판정해요.** bioRxiv 세트와 합친 결과는 분석 보고서의 보조 수치로만 적어요. 두 분야에서 각각 신호가 나오는 것이 합친 수치보다 강한 근거예요.
- 분석 보고서는 `reasonlineage gold --analysis`를 그대로 써요.

## 7. 오류 처리
bioRxiv 설계 7을 그대로 쓰고, 다음을 더해요.
- **arXiv API 실패:** 페이지마다 쉬었다가 다시 받아요(최대 4번). 그래도 실패하면 어느 페이지인지 알리고 멈춰요.
- **정리할 수 없는 수식:** 그 논문을 빼고 사유를 적어요.
- **제공자 거부:** bioRxiv와 같아요. 논문을 빼기 전에 이미 정상으로 돌아간 과제로 대조 확인을 먼저 해요. 그것도 거부되면 제공자 상태 문제이니 기다려요.

## 8. 테스트
모델과 arXiv는 부르지 않아요. 가짜 응답을 써요.
- **수집 거르기:** 버전(v1), 날짜 경계, 주 분류, 초록 길이, 페이지 넘기기를 확인해요.
- **수식 정리:** 4.2의 변환표와, 정리 못 하는 초록을 버리는지 확인해요.
- **공용 모듈 이동:** 옮긴 뒤 bioRxiv 테스트가 그대로 통과하는지 확인해요.
- **파일:** 엔진이 과제를 읽는지, 정답 파일이 채점 코드를 통과하는지, 제목이 새지 않는지, 글자 배분이 고른지 확인해요.
- **스크립트:** `build_arxiv.py` 세 단계의 인자와 오류 안내를 확인해요.
