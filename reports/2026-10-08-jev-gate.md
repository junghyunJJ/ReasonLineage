# jev 점검·재작성 연결 — 2026-10-08

**새 `--jev` 실행 경로에 J1 재작성과 J2 기록을 연결했다. DeepSeek는 이 경로에서 만들거나 호출하지 않는다. 실제 ALS·AML 생성 재시험은 아직 시작하지 않았다.**

현재 세 모델은 GPT 6.1 sol, Grok 4.7, GLM 5.3 Flash다. 초기에는 각 모델이 가설을 하나씩 생성해 총3개로 출발한다. 작성자를 제외한 두 모델이 채점하고, 가설2개를 생존시킨 뒤 변이1개·교차1개를 생성해 이후 세대는4개를 유지한다. 초기 이후3세대를 반복한다. jev는 새 가설을 패널이 채점하기 전에 점검한다.

## 재작성의 명확한 기준

| 검사 | 재작성 조건 | 판정 범위 |
|---|---|---|
| 답변 유형 | 정상 답변 확률 <0.5 | 질문에 대한 답변인지, 거절·메타 문구·채점자에게 말 걸기인지 |
| 구체적인 논증 | 논증이 있다는 확률 <0.5 | 가설에 구체적 이유·제안 기전·근거 연구가 적혀 있는지 |
| 논증 충실도 | 재작성에 사용하지 않음 | 기록용 |

둘 중 하나라도 기준 미달이면 같은 작성자가 최대1회 다시 작성한다. **0.5와 같은 값은 통과**다. 논증 여부 질문에는 다음 구분을 명시했다: 제안 답변만 보고, 논증의 존재를 판단하며, 사실·검증 여부·신규성·강도를 판정하지 않는다. 분명히 가설로 표시한 기전도 논증으로 인정하고, 이름만 고른 것은 논증으로 인정하지 않는다. 과학적 타당성과 유망도는 계속 패널 심사의 대상이다.

수정문을 다시 점검한다. 남은 결함은 원 HTML 설계대로 기록하고 채점으로 넘긴다. jev가 후보를 삭제하거나 점수·fitness·선택을 결정하지 않는다. 재작성은 추가 세대가 아니라 같은 후보의 수정 버전이다. 원문과 수정문은 호출 기록에 모두 남는다. 수정문이 원문과 같아도 시도0·1 판정과 잔여 결함을 기록하며, 같은 판정에 대한 외부 요청은 캐시로 재사용할 수 있다.

## 실제 서비스로 기준 확인

확률 임계값0.5를 고정한 채, 두 과제와 세 표현에 정상·거절·메타·채점자에게 말 걸기·논증 누락을 넣어 수동 구성한30개 사례를 검사했다. 이 사례들은 실제 모델이 만든 연구 가설의 품질 점수를 측정하는 자료가 아니다.

| 단계 | 실제 요청 | 결과 |
|---|---:|---|
| 원래 질문 문구 |30|29/30 일치, 정상답변1개 오탐 |
| 오탐 입력의 고정 문구 진단 |4|기존 문구의 논증 확률0.48/0.50, 범위를 명확히 한 문구0.94/0.95 |
| 명확히 한 문구로 개발 예시 |30|30/30 일치, 오탐0·놓침0 |
| 새 본문·표현의 별도 예시 |30|30/30 일치, 오탐0·놓침0 |

최초 오탐에서 정상 답변에는 NUP98의 기전과 반증 조건이 있었지만 논증 확률0.45가 반환됐다. 논증 충실도는 높은 값이어서 두 질문의 판정도 일관되지 않았다. 공급자는 서술형 판단 이유를 반환하지 않아 내부 원인을 확정할 수는 없다. 존재 판정과 과학적 검증을 구분하도록 질문을 명확히 했고 임계값을 조정하지 않았다. 원래 실패 기록을 삭제하지 않았다.

최소 활성화 조건은 두30개 묶음 모두 정상6개·의도결함24개를 기대대로 판정하는 것이다. 질문·임계값·모델 버전과 검증 자료의 해시를 프로필에 묶었다. 변경되면 기존 검증으로 자동 활성화할 수 없다. **이 작은 구조 결함 예시의 통과를 실제 과학 가설 전반의 정확도로 주장하지 않는다.**

## J2와 오류 처리

실행이 끝나면 최종적으로 채점한 가설의 문체 과장과 패널 비판의 심각도를 jev가 기록한다. 비판 심각도는 비판문이 주장하는 문제의 심각도이며 그 주장의 진실 여부 판정은 아니다. 문체·비판 결과는 재작성이나 선택에 영향을 주지 않는다. 임상 결과 언급은 확인된 정답 결과 목록이 없어서 생략한다. 전문가 평가는 아직 대기 상태다.

점검 요청 실패는 판정 불가로 기록하고 원 설계처럼 생성·진화를 계속한다. 생성 완료와 점검 완료를 구분해 J1/J2를 `partial`로 표시하고 전체 CLI 성공으로 처리하지 않는다. 고정한 `jev-1.13.0`과 응답 버전이 다르면 상태를 저장하고 해당 실행뿐 아니라 다음 연구 슬롯도 중단한다.

## 사용량과 확인된 범위

이번 실제 서비스 요청은 **jev94회**, 보고 입력170,111·출력7,726·합계177,837토큰, 미확인 사용0건이다. 최초 실패와4회 진단을 모두 포함했다. 실제 가설 생성·DeepSeek 호출은0회다. 공급자가 비용 필드를 반환하지 않아 실제 청구액은 알 수 없다.

새 전체 실행은 ALS·AML × 다중/GPT/Grok/GLM의8개 슬롯이다. 슬롯마다 정상 작성·패널심사27호출, 재작성은 가설당 최대1회다. 검사 사용량은 별도 `checker_usage`와 전역 합계에 모두 기록한다. 생성 상한40회·jev 상한50회를 분리했고, 새모드의 전역 상한은724회다. 이는 향후 실행의 상한이며 이번에 사용한 호출 수가 아니다. DeepSeek 별도 평가 요청은 포함되지 않는다.

관련 검증45개와 최종 전체 오프라인769개가 통과했다(live3개 제외). 코드 검토에서 J1 버전 불일치 후 다음 슬롯이 계속되는 문제와 동일 수정문 재검사의 기록 누락을 발견해 RED 재현 후 수정했다. 해당 회귀를 포함한 gate/jev14개가 통과했고 재검토에서 추가 주요 문제가 없었다. 검사 API와 보안 변경은 기존 프로필에서도 회귀 검증했다. 이전 ALS77개·AML155개·jev494개 자료의 해시는 모두 유지됐다.

## 키 처리와 발견된 셸 문제

새 경로는 공유 저장소 루트 `.env`의 `JEV_API_KEY`만 직접 읽고 셸 실행·확장·환경 출력 없이 사용한다. 키와 인증 헤더는 기록하지 않고 HTTP/파싱 오류의 공급자 원문도 출력하지 않는다. 새 검증 자료에서 실제 키 문자열이 없음을 확인했다.

코드 검토 도구가 첫 두 명령에서 `login:false`를 지정하지 않아 기존 셸 초기화가 실행되며 API키처럼 보이는 문자열이 도구 오류 출력에 나타났다. 실제 유효성은 확인하지 않았다. 사용자에게 알리고 값을 반복하지 않았다. 이후 모든 검토 명령에 `login:false`를 강제했다.

원인은 `.bashrc`에서 키만 담긴 `jev.env`를 셸 코드로 실행하는 구문1개였다. 해당 구문만 비활성화하고 원본을 권한600의 백업으로 보존했다. 셸을 실행하지 않는 구문검사가 통과했다. 키 파일의 값이나 루트 `.env`를 수정하지 않았다. **노출된 유효 키의 폐기·교체는 사용자 조치가 필요하며 완료됐다고 주장하지 않는다.**
